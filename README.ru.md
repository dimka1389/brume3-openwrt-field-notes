# Brume 3 / GL-MT5000: заметки о тестировании OpenWrt

[English](README.md) · [Свежий отчёт](docs/2026-11-14.ru.md) · [Сообщить о проблеме](https://github.com/dimka1389/brume3-openwrt-field-notes/issues/new/choose) · [Обсуждения](https://github.com/dimka1389/brume3-openwrt-field-notes/discussions)

Независимый двуязычный журнал испытаний одного розничного GL.iNet Brume 3 с экспериментальной OpenWrt. Собираем проверяемые наблюдения, полезные другим тестировщикам и разработчикам.

Здесь опубликованы материалы испытаний. Готовой прошивки для скачивания нет. Это не официальный проект OpenWrt, GL.iNet или StealthSurf. Работа одного устройства не доказывает безопасность образа для всех пользователей.

## Проверенная основа

| Компонент | Наблюдение на 14.11.2026 |
|---|---|
| Устройство | GL.iNet GL-MT5000 / Brume 3 |
| Платформа | `mediatek/filogic`, `aarch64_cortex-a53` |
| Обозначение сборки | OpenWrt SNAPSHOT `r0-1713e8b` |
| Исходная основа | `GLiNet-Tech/openwrt`, коммит `1713e8be63b628fe2f1d336f4fb3a8aa152875af` |
| Ядро | Linux `6.18.60` |
| Межсетевой экран | fw4 / nftables |
| Проверенные соединения | Действующий IPv4 PPPoE, LAN, DNS, SSH, LuCI, прозрачный VPN |
| StealthSurf | Вручную обновлена с `1.0.101` до `1.0.106` |
| Системные пакеты | 26 обновлений проверенными группами; закрепление ядра, libc и base-files этой сборки сохранено |

До обслуживания устройство работало около шести суток. Образ прошивки и ядро не заменялись. После обновления пакетов по просьбе владельца выполнена одна перезагрузка: SSH вернулся, запущен новый procd, PPPoE переподключился, StealthSurf подключилась автоматически. HTTPS напрямую и через VPN работает. Восстановление после потери питания и длительная работа ещё не проверены.

## Что обнаружено

- Ночное самообновление StealthSurf многократно останавливало приложение. Ранее установленный локальный watchdog возвращал его в работу. Ручной запуск официального установщика вне службы приложения завершился успешно.
- Стандартная резервная копия OpenWrt не включала каталог учётной записи и настроек StealthSurf в этой установке. Потребовался отдельный приватный архив.
- Подробный журнал Xray перестал расти примерно на 8 МиБ. После обновления и перезапуска приложения запись возобновилась. Также наблюдалась ошибка ротации `Bad file descriptor`; её причина пока не установлена.
- После каждой группы пакетов прошли пробы HTTPS напрямую и через VPN. Это не заменяет проверку приложений, видео, переключения резервов, IPv6, коммутации LAN-to-LAN и длительной нагрузки.

Испытания и решения о публикации: владелец устройства. Диагностика и подготовка текста: при участии Codex. Соавторство относится к испытаниям и документации, а не к чужой прошивке или приложению.

## Как участвовать

Конкретные воспроизводимые ошибки — в [Issues](https://github.com/dimka1389/brume3-openwrt-field-notes/issues/new/choose), вопросы и сравнение результатов — в [Discussions](https://github.com/dimka1389/brume3-openwrt-field-notes/discussions). Можно писать на русском и английском. Сначала прочитайте [CONTRIBUTING.md](CONTRIBUTING.md).

Личные образы, резервные копии, конфигурации и подписки не публикуются. Для распространения готовой прошивки нужна отдельная чистая сборка без встроенных паролей, ключей и данных устройства, сведения о воспроизводимости и проверка восстановления. Чужую личную резервную копию прошивать нельзя.

[Основа для чистой сборки](docs/clean-build.md) — готового образа для скачивания пока нет.
