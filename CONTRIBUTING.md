# Contributing / Участие

Russian and English contributions are welcome. / Принимаются сообщения на русском и английском.

1. Read [PRIVACY.md](PRIVACY.md) before posting. / Перед публикацией прочитайте правила конфиденциальности.
2. Use Issues for a reproducible failure; use Discussions for questions and comparisons. / Воспроизводимая ошибка — в Issues, вопросы и сравнение опыта — в Discussions.
3. State the exact hardware model, source revision, kernel and relevant package/app versions. / Укажите точную модель, ревизию исходников, ядро и версии нужных пакетов или приложения.
4. Separate observation, hypothesis, workaround and confirmed fix. / Разделяйте наблюдение, гипотезу, временное решение и подтверждённое исправление.
5. Describe one change at a time and the tests after it. Say if a reboot, reconnect or actual rollback was not tested. / Описывайте по одному изменению и проверкам после него; отмечайте непроверенные перезагрузку, переподключение и откат.
6. Credit relevant upstream work with precise links. A link does not notify its authors. Avoid repeated unsolicited mentions. / Ссылайтесь на исходные проекты точно; ссылка сама не уведомляет автора. Избегайте повторяющихся незапрошенных упоминаний.

Do not promise universal compatibility based on one unit. Do not post a personal firmware image or ask another tester to flash a private backup. An upstream report should contain only the minimal relevant, reviewed information.

Работа одного экземпляра не подтверждает универсальную совместимость. Не публикуйте образ личной установки и не предлагайте другим прошивать приватный бэкап. В обращение к разработчикам включайте только минимальные проверенные сведения по конкретной проблеме.
